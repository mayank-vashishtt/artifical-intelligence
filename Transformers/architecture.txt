why we need positional encoding after word2vec or embedding ?
- Embeddings capture word meaning but not order
- Positional encodings add sequence order information
but word2vec capture order too in some way right ?
Word2Vec captures semantic relationships between words based on their context, but it does not explicitly encode the order of words in a sequence. 
For example, Word2Vec can learn that "king" and "queen" are related, but it does not capture the fact that "the cat sat on the mat" has a specific order that is different from "the mat sat on the cat."


Positional Encoding?
- Adds sequence order information to input embeddings
- Since transformers process inputs in parallel, positional encodings help retain the order of tokens
- Typically implemented using sine and cosine functions of different frequencies

why we dont do indexing as positional encoding ?
Indexing is a discrete representation and does not provide a continuous sense of position. Positional encodings, 
on the other hand, use continuous functions (like sine and cosine) to represent positions,

frequency based encoding?
- Uses sine and cosine functions at different frequencies to encode positions
- Allows model to learn relative positions and distances between tokens
- Provides a continuous representation of position

how it works ? 
- For each position in the sequence, compute sine and cosine values using different frequencies
- Combine these values to create a positional encoding vector
- Add positional encoding vectors to input embeddings before feeding them into the transformer model
- This way, the model can differentiate between tokens based on their positions in the sequence
